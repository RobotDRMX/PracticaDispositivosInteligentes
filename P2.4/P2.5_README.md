# Práctica 2.5: Integración de la API OpenWeatherMap 🌍⛈️

Esta práctica corresponde al módulo de **Dispositivos Inteligentes**. En esta fase del proyecto **Climate App**, se implementa la integración completa con la API de clima **OpenWeatherMap**, permitiendo la consulta de condiciones meteorológicas en tiempo real de cualquier ciudad, con manejo exhaustivo de excepciones de red y gestión de estado robusta mediante el patrón **Provider**. Asimismo, se preserva la compatibilidad con el escaneo y adquisición de datos de wearables **Bluetooth Low Energy (BLE)** desarrollados en la práctica anterior (P2.4).

---

## 🚀 Características Clave

*   **Consulta de Clima en Tiempo Real:** Obtención dinámica de datos meteorológicos (temperatura, descripción del clima, humedad y velocidad del viento) mediante peticiones HTTP REST a OpenWeatherMap.
*   **Manejo Robusto de Errores y Excepciones:**
    *   **HTTP 401:** Detección de API Keys inválidas o inactivas.
    *   **HTTP 404:** Manejo amigable de ciudades no encontradas.
    *   **HTTP 429:** Control del límite de llamadas a la API.
    *   **Red / Timeouts:** Control de falta de conexión a Internet (`SocketException`) y expiración de tiempo de respuesta (`TimeoutException`).
*   **Conversión Dinámica de Unidades:** Permite alternar la visualización del clima entre grados **Celsius (°C)** y **Fahrenheit (°F)** al instante.
*   **Interfaz Dinámica y Responsiva:** Actualización visual de íconos meteorológicos representativos (`☀️`, `☁️`, `🌧️`, `🌩️`, `❄️`, etc.) con base en los códigos de condición retornados por la API.
*   **Integración BLE Wearable:** Se conserva la capacidad de vincular con wearables a través de Bluetooth Low Energy para complementar datos ambientales locales y corporales.
*   **Listado de Ciudades:** Buscador inteligente con filtro y acceso directo a ciudades preconfiguradas para pruebas rápidas.

---

## 🛠️ Tecnologías y Dependencias Utilizadas

*   **Flutter & Dart SDK** (`>= 3.12.0`)
*   [**http**](https://pub.dev/packages/http) (`^1.2.1`): Cliente HTTP optimizado para el consumo de la API de OpenWeatherMap.
*   [**flutter_dotenv**](https://pub.dev/packages/flutter_dotenv) (`^5.1.0`): Carga segura de variables de entorno desde un archivo `.env` externo, previniendo la exposición pública de API Keys.
*   [**provider**](https://pub.dev/packages/provider) (`^6.0.0`): Arquitectura de gestión de estado reactiva y desacoplada.
*   [**flutter_blue_plus**](https://pub.dev/packages/flutter_blue_plus) (`^1.31.0`): Suite de integración de conectividad Bluetooth Low Energy para wearables.

## 📂 Arquitectura y Estructura del Código de Clima

La arquitectura sigue una separación limpia de responsabilidades dentro de la carpeta `lib`:

```
lib/
├── config/
│   └── app_config.dart          # Lee las variables del entorno (.env) de forma segura
├── models/
│   └── weather_model.dart       # Modelo de datos que parsea el JSON de OpenWeatherMap
├── providers/
│   └── weather_provider.dart    # Maneja el estado global del clima, BLE y cambios de UI
├── screens/
│   ├── home_screen.dart         # UI principal: Clima actual, botón de unidades y accesos
│   ├── search_screen.dart       # Filtro y selección de ciudades predeterminadas
│   └── ble_scan_screen.dart     # Interfaz de escaneo y vinculación de wearables BLE
├── services/
│   ├── weather_service.dart     # Servicio REST que consume e interpreta la API de OpenWeatherMap
│   └── ble_service.dart         # Servicio de bajo nivel para comunicación Bluetooth BLE
├── utils/
│   └── weather_utils.dart       # Conversión de temperaturas y mapeo de íconos climáticos
└── widgets/
    ├── temperature_card.dart    # Componente reutilizable para visualización de temperatura
    └── weather_icon.dart        # Componente visual para íconos meteorológicos
```

## 🔐 Configuración de Seguridad y Variables de Entorno

Por motivos de seguridad informática, las credenciales de OpenWeatherMap están protegidas a través de un archivo de configuración `.env` en la raíz del proyecto Flutter (`climate_app/.env`). Este archivo se encuentra explícitamente ignorado en el sistema de control de versiones `.gitignore`.

### Configurar el archivo `.env`

Para ejecutar este proyecto de manera local, crea un archivo `.env` dentro del directorio `climate_app/` con la siguiente estructura:

```env
OPENWEATHER_API_KEY=tu_api_key_aqui
OPENWEATHER_BASE_URL=https://api.openweathermap.org/data/2.5/weather
```

> **Nota:** Puedes obtener tu API Key de forma gratuita registrándote en [OpenWeatherMap](https://openweathermap.org/).

## 💻 Instrucciones para Ejecución Local

1.  **Navega al directorio de la aplicación móvil:**
    ```bash
    cd climate_app
    ```
2.  **Crea y configura el archivo de entorno `.env`** según las instrucciones del apartado anterior.
3.  **Obtén las dependencias de Flutter:**
    ```bash
    flutter pub get
    ```
4.  **Ejecuta la aplicación:**
    ```bash
    flutter run
    ```
